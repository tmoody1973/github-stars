# 005 — Write each daily post for non-technical readers, with specifics for engineers

**Decision** — Every daily post is written so a smart person outside tech can follow it: each project is described by what it does for a person, and technical terms are explained in a few everyday words or replaced. Each entry still keeps one concrete detail from the project's README.

**Why this came up** — The first published post (2026-10-14) was accurate but written for engineers: "1-bit LLMs", "GraphRAG", "vLLM", "KS tests". Tarik's LinkedIn audience includes people in media, nonprofits and business who would stop reading at the first entry. Posts that only engineers can read get fewer shares outside that group.

**Options**
- **One post for everyone** — plain English first, jargon explained in passing, one specific detail kept per entry. Cost: engineers read a few explanations they don't need; posts run a little longer.
- **Two versions per post** — a plain and a technical version with a toggle on the blog and a copy button for each. Cost: about twice the writing calls each day, a second quality check, a database change, and Tarik still pastes only one.
- **Plain English only** — drop the technical detail. Cost: engineers lose the specifics (speedups, supported platforms) that make a recommendation credible.

**What we chose and why** — One post for everyone. Claude recommended it and Tarik chose it. LinkedIn gets one post a day either way, so the version that more people can read and share is the one worth writing. Keeping one concrete detail per entry stops it from turning into marketing fluff.

**What we gave up** — A version tuned only for engineers, and some brevity.

**How we'll know if this was right** — The reading level of posts (roughly, the school grade needed to follow the text) drops compared with the first post, and over the next month Tarik sees comments or shares from people outside tech.
